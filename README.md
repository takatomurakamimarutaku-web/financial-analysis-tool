# 数字のミカタ

「数字のミカタ」は、iPhone のブラウザで使える財務分析ツールです（名前は、決算書の数字の「見方」がわかり、分析の「味方」になる、という意味です）。HTML / CSS / JavaScript のみで作成しており、ビルドや外部ライブラリは使っていません。

- 金額単位：千円（設定で区分ごとに円・百万円にも切り替え可能）
- 画面：濃紺のアプリバー、見出し帯・罫線・しま模様の表など、業務用会計ソフトのような落ち着いた配色（ダークモード対応。フォントは端末内蔵のヒラギノ角ゴシック等を使用し、外部フォントは読み込まない）
- データはこの端末のブラウザ（localStorage）にのみ保存し、外部へは送信しません
- 計算結果の丸めは表示時のみ行い、内部では丸めません

## 機能

### Phase 1：単一期の財務指標計算

- PL 8項目・BS 11項目を入力すると、20指標を即時に再計算してカテゴリ別に表示
- 各指標をタップすると「計算式」と「一般的な見方」を展開
- サンプルデータ読込 ／ クリア ／ 結果をテキストでコピー
- 貸借の不一致チェック（差額を表示）、債務超過の警告
- 入力内容は自動保存（次回開いたときに復元）

### Phase 2：複数期比較（最大5期）

- 「入力」タブ：期の追加（期名は「2025/3期」→「2026/3期」のように自動提案）・削除・並べ替え（←→）・期名の編集。左が古い期です
- 「比較」タブ：行＝指標、列＝各期の比較表。前期比（増減額・増減率）を表示（非表示にも切替可）
  - スマホでは横スクロールでき、指標名の列は固定表示
- 主要指標（売上高・営業利益・EBITDA・営業利益率・自己資本比率）の推移グラフ（SVG で自作、外部ライブラリなし）
- 期末残高ベース／平均残高ベースの切り替え
- サンプルデータは 2023/3期〜2025/3期 の3期分（2025/3期は Phase 1 のサンプルと同じ数値）

#### 前期比の計算

| 項目 | 計算 | 表示 |
| --- | --- | --- |
| 増減額 | 当期 − 前期 | % の指標はポイント（pt）、その他は各単位 |
| 増減率 | (当期 − 前期) ÷ 前期 | 前期が 0 →「—」、前期がマイナス →「参考外」、どちらか未入力 →「—」 |

「前期」は比較表で1つ左の列の期です。

#### 平均残高ベース

- 平均残高 = (前期末 + 当期末) ÷ 2
- 対象：ROA、ROE、売上債権回転日数、棚卸資産回転日数、仕入債務回転日数、CCC（比較表で★印）
- 前期データがない期（先頭の期）は「—」
- 平均自己資本がマイナスの場合、ROE は「参考外」
- 対象外の指標は期末残高で計算します

### 入力のしかた

- カンマ・全角数字も入力できます（例：`１，２３４` → 1,234）
- マイナスは「±」ボタンで符号を反転します（iPhone の数字キーボードにマイナス記号がないため）。貼り付けの場合は `-500`、`△500`、`▲500` も負数として扱います
- 空欄は「未入力」として扱い、0 とはみなしません

### 図解タブ

選択中の期（入力タブと連動）のデータを図で表示します。各図に、数値から自動で作る一文の説明と「この図の見方」を付けています。金額は「分析結果・比較表・グラフ」の単位です。

| 図 | 内容 |
| --- | --- |
| 損益の滝グラフ | 売上高 → −売上原価 → 売上総利益 → −販管費 → 営業利益 → ±営業外損益 → 経常利益 → ±特別損益・税金等 → 当期純利益（売上高・売上原価・販管費・営業利益が必要。経常利益・当期純利益は入力があれば表示） |
| BSの面積図 | 資産（流動・固定）と負債・純資産（流動負債・固定負債・純資産）を金額に比例した箱で表示。債務超過の場合は資産側に「債務超過」の箱を置く |
| お金が戻るまでの日数 | 在庫日数＋売掛金の回収日数、仕入代金の支払日数、その差の CCC を帯で表示（CCC がマイナスなら「支払より先に回収」） |
| EBITDAの正常化 | 報告EBITDA → 区分ごとの調整 → 正常化EBITDA の滝グラフ |
| 実質的な借入 | 有利子負債 ＋ デットライク − 現預金 − キャッシュライク ＝ 調整後ネットデット の滝グラフ |

図は `js/diagrams.js`（DOM に依存しない純粋関数）で SVG を生成します。指標のレーダーチャートは、評価基準を決めてから追加予定です。

### サマリー・整合チェック

- 入力タブの先頭に、選択中の期の「売上高」「営業利益（営業利益率）」「EBITDA（調整項目がある期は正常化EBITDA）」「自己資本比率」と前期比を表示
- PL の整合チェック：売上高・売上原価・販管費・営業利益がすべて入力されていて、営業利益 ≠ 売上高 − 売上原価 − 販管費 のとき、差額つきで警告（BS の貸借チェックと同じく 0.5円未満の差は無視）

### 画面の移動（ジャンプメニュー）

- 画面上部にタブと「項目メニュー」を固定表示します。項目名をタップすると、その位置へスクロールします（閉じている PL/BS 入力は自動で開きます）
- 入力タブ：サマリー／基本情報／PL入力／BS入力／分析結果／正常化EBITDA／運転資本・ネットデット／バックアップ
- 比較タブ：基準／比較表／EBITDAブリッジ／運転資本／ネットデット／グラフ／出力
- いま表示中の項目は青枠で示します。レポート表示中はメニューを隠します

### Phase 1.5：PWA化（ホーム画面に追加・オフライン動作）

- iPhone の Safari で「ホーム画面に追加」すると、アプリとして全画面で起動します
- 一度開けば、機内モードなどのオフラインでも起動・入力・計算ができます
- 新しいバージョンを公開すると、画面下に「新しいバージョンがあります［更新］」が表示されます。［更新］を押したときだけ切り替わります（勝手には切り替わりません）
- データのバックアップ（JSON）と復元
  - 「バックアップを保存」：iPhone では共有シートが開くので「"ファイル"に保存」を選びます（共有できない環境ではダウンロード）
  - 「バックアップから復元」：形式（`format`）とバージョンを検証し、不正なファイルは読み込まずにエラーを表示します
  - 最終バックアップ日時を表示し、30日以上（または一度も）バックアップしていない場合は案内を表示します
- 対応環境では `navigator.storage.persist()` で保存データの永続化を要求します（非対応でもそのまま動作します）

> ホーム画面アプリの保存データは、iOS の判断（空き容量不足、長期間未使用など）で削除されることがあります。定期的にバックアップしてください。

#### バックアップファイルの形式

```json
{
  "format": "finAnalysisTool-backup",
  "formatVersion": 1,
  "exportedAt": "2026-10-24T06:00:00.000Z",
  "data": { "version": 1, "companyName": "…", "periods": [ … ] }
}
```

### Phase 3：正常化EBITDA

- 各期に調整項目を複数登録できます（入力タブの「正常化EBITDA」欄）
  - 項目：区分、内容、金額（プラス＝EBITDAに加算、マイナス＝減算）、根拠メモ
  - 区分：役員報酬の調整／一過性の損益／関連当事者取引／会計方針の差異／事業の撤退・新設／その他
- 正常化EBITDA ＝ 報告EBITDA ＋ 調整額合計
- 正常化EBITDAマージン ＝ 正常化EBITDA ÷ 売上高
- EBITDAブリッジ表（報告EBITDA → 区分ごとの調整 → 調整額合計 → 正常化EBITDA → マージン）
  - 入力タブ：選択中の期 ／ 比較タブ：全期（調整項目のある区分のみ行を表示）
- 比較表に「正常化EBITDA」「正常化EBITDAマージン」の行を追加（前期比も表示）
- 根拠メモが空の調整項目には「根拠未記載」、金額が空の項目には「金額未入力」を表示（金額未入力の項目は合計に含めません）
- 報告EBITDA（営業利益・減価償却費）が未入力の期は、正常化EBITDAも「—」

### Phase 4：運転資本・ネットデットの分析

- 運転資本（トレード）＝ 売上債権 ＋ 棚卸資産 − 仕入債務
  - 期別推移と売上高に対する比率（運転資本 ÷ 売上高）を表示
  - 参考：平均運転資本 ＝ 運転資本が計算できた期の単純平均。比率は「平均運転資本 ÷ 同じ期の平均売上高」
  - 注記：本来は月次残高で算定すべきものであり、本値は期末残高による簡易的な目安
- デットライク項目（例：退職給付引当金、未払法人税等、リース債務、未払配当、役員退職慰労引当金）と
  キャッシュライク項目（例：定期預金、換金性の高い有価証券、保険積立金）を各期に登録（名称・金額・根拠メモ）
- 調整後ネットデット ＝ 有利子負債 ＋ デットライク項目 − 現預金 − キャッシュライク項目
- 調整後ネットデット ÷ 正常化EBITDA（正常化EBITDA がマイナスなら「参考外」、0 なら「—」）
- デットライク・キャッシュライク項目が0件の場合、調整後ネットデットは Phase 1 のネットデットと一致
- 比較タブ：運転資本の推移表（参考：平均の列つき）、ネットデット内訳表（項目は名称ごとに全期をそろえて表示）
- 比較表に「運転資本（トレード）」「運転資本 ÷ 売上高」「調整後ネットデット」「調整後ネットデット ÷ 正常化EBITDA」の行を追加
- 根拠メモが空の項目は「根拠未記載」、金額が空の項目は「金額未入力」（合計に含めない）

### Phase 5：出力・保存

- CSV出力（比較タブの「出力」欄）。Excel で文字化けしないよう **BOM 付き UTF-8**、改行は CRLF
  - 比較表CSV：区分・指標・単位・各期の値・2期目以降の増減額／増減率(%)。選択中の基準（期末／平均残高）で出力
  - EBITDAブリッジCSV：ブリッジ表 ＋ 調整項目の明細（根拠メモ）
  - ネットデット内訳CSV：内訳表 ＋ デットライク・キャッシュライク項目の明細
  - 数値は丸めずに出力（浮動小数点の誤差のみ除去）。% の指標はパーセント値、計算できない値は空欄、参考外は「参考外」
  - カンマ・改行・ダブルクォートを含む文字列は `"` で囲み、`"` は `""` に置き換え。`= + - @` で始まる文字列は数式として実行されないよう先頭に `'` を付与
  - ファイル名：`fin-tool-comparison-YYYY-MM-DD.csv` など（英数字のみ）
- 印刷用レポート（A4縦）：会社名・対象期・作成日・主要指標・EBITDAブリッジ・正常化調整の明細・ネットデット内訳・運転資本・警告・注記
  - iPhone：レポート画面の「印刷・PDF保存」→ 共有ボタン →「"ファイル"に保存」でPDF保存
  - **レポートの仕上げ（段階B No.11）**：レポート画面の「レポートの内容」で設定（印刷には出ない）
    - 作成者・事務所名（全社共通。表紙と見出しに表示）
    - 所見コメント（会社ごと。最大2000文字。主要指標の前に「所見」として表示）
    - 表紙（会社名・対象期・作成日・作成者・免責。印刷時は1ページ目に単独）、グラフ・図解（比較タブの推移グラフ5種と、最新期の損益の滝グラフ・BSの面積図）、ページ番号（印刷時に下部中央に「1 / 5」）。それぞれオン・オフ可（既定はオン）
    - ページ番号は CSS の `@page` の余白ボックスで付けるため、対応していないブラウザでは付かない（Chromium では確認済み、iPhone の Safari は未確認）
- JSON バックアップ・復元（Phase 1.5 で実装済み。過去のすべての version を読み込み、最新形式へ移行）
- 「すべてのデータを削除」：確認ダイアログを経て、入力データと最終バックアップ日時をこの端末から削除

### Phase 6：設定ページ

「設定」タブ → 項目一覧 → 各設定画面の2段構成。設定はデータ（`data.settings`）に保存し、JSONバックアップにも含めます。

| 設定 | 内容 |
| --- | --- |
| 会社の管理 | 会社の追加・選択・並べ替え・名前変更・複製・削除、全社のバックアップ、保存データの大きさ |
| 金額の単位 | 円／千円／百万円を**区分ごと**に選択（PL入力、BS入力、正常化EBITDA、運転資本・ネットデット、分析結果・比較表・グラフ、印刷用レポート・CSV の6区分。「すべて円」などでまとめて変更も可）。**内部の金額は常に千円**で、入力・表示のときだけ換算（百万円は小数第1位まで表示）。切り替えても保存済みの金額は変わらない |
| PL科目・BS科目 | 並び替え（↑↓）、表示名の変更（空欄で標準名に戻る）、表示/非表示、内訳科目の追加・削除・並び替え・名称変更 |
| 指標の表示・並び順 | 指標ごとの表示/非表示と、区分内の並び順。入力タブの分析結果・比較表・比較表CSV・結果テキストに反映（印刷用レポートは常に主要指標を掲載） |
| 評価基準（バッジ） | 標準／古田土会計／日本政策金融公庫（業種を選択）／TKC（自分で入力）の切り替え、指標ごとの境界の変更・バッジのオン/オフ（詳しくは「評価バッジ」） |
| 分析の基本設定 | 回転日数の1年の日数（365日／360日）、比較タブの計算基準の初期値（期末残高／平均残高） |
| 画面の表示 | 表示テーマ（端末の設定に合わせる／ライト／ダーク）、マイナスの表示（−1,000／△1,000）。△は画面・入力欄・レポートに適用し、CSV は数値のまま |
| 表示桁数 | %（前期比の pt・増減率を含む）、日、倍・回の小数点以下の桁数。計算は丸めず表示時のみ四捨五入 |
| 正常化EBITDAの調整区分 | 区分の表示名の変更（追加・削除は不可） |
| バックアップ・データ管理 | バックアップの案内間隔（7〜90日／案内しない）、バックアップの保存・復元、設定を初期値に戻す、すべてのデータを削除 |
| 指標の解説（計算式一覧） | 全指標の計算式・意味・現在の評価基準での目安、計算できない場合の表示 |
| このアプリについて | バージョン、データ形式、保存データの保護状態、「更新を確認」「使い方ガイドを見る」、免責事項、プライバシー、著作権・ライセンス、お問い合わせ（準備中） |

科目設定のルール：

- 計算に使う標準科目（売上高・営業利益など）は**削除不可**。使わない科目は非表示にする（入力済みの値は計算に使われる）
- 内訳科目は標準科目の下に追加する。**内訳に金額を入れた期は、親科目 ＝ 入力済みの内訳の合計**で自動計算（親科目の欄は編集不可）。内訳がすべて未入力の期は親科目の入力値を使う
- 親科目に金額が入力済みの状態で最初の内訳を追加すると、合計が変わらないよう「その他」の内訳を自動で作り、元の金額を移す
- 内訳を削除すると全期の値も削除し、残りの内訳で親科目を再計算する（最後の内訳を削除した場合は直前の金額のまま入力欄に戻る）。内訳は全体で60件まで
- 名称変更は入力画面、比較表の金額行、運転資本・ネットデットの表に反映。指標の計算式の説明は標準名のまま
- 内訳で親科目が変わっても、営業利益など他の科目は自動では変わらない（入力値のまま）
- 「クリア」「サンプルデータ読込」では設定を残し、「すべてのデータを削除」「設定を初期値に戻す」で初期値に戻る

### 評価バッジ（評価基準）

分析結果・サマリー・比較表・印刷用レポートの指標に「良好」「注意」のバッジを付けます（どちらでもなければバッジなし）。色だけでなく文字で示します。

- 現在の基準は分析結果と比較表の上に「評価基準：○○」と表示し、タップすると設定の「評価基準（バッジ）」を開きます
- 指標の詳細に「評価の目安」（境界値と基準名、公庫は平均値・中央値）を表示します
- 判定は丸める前の値で行い、境界の値は良好側（以上・以下）に含めます。期末・平均残高ベースとも同じ境界です
- 分母0・未入力・参考外はバッジなし。自己資本比率がマイナスは「注意（債務超過）」、ROE は自己資本比率が注意のとき良好にしない、ICR は支払利息0で営業黒字なら「良好（利息負担なし）」、ネットデット倍率はネットキャッシュなら「良好（実質無借金）」・借入ありでEBITDA赤字なら「注意（EBITDA赤字）」
- 回転日数・CCC・金額の指標は評価しません

| 基準 | 内容 |
| --- | --- |
| 標準 | 一般的な目安（例：営業利益率 良好5%以上／注意0%未満、流動比率 150%以上／100%未満、自己資本比率 30%以上／10%未満、D/E 1倍以下／2倍超、ネットデット倍率 3倍以下／5倍超） |
| 古田土会計 | 自己資本比率 60%以上／30%未満、ROA 10%以上／5%未満、流動比率 200%以上／100%未満、当座比率 100%以上、総資産回転率 2.5回以上／1.5回未満。ほかは標準 |
| 日本政策金融公庫 | 「小企業の経営指標調査」業種別経営指標（業種全体の表）。9業種（建設業・製造業は2024年度、ほかは2025年度調査）×9指標。良好＝黒字かつ自己資本プラス企業平均以上、注意＝中央値未満（低いほど良い指標は逆）。平均が中央値より悪い指標は中央値を良好の境界にも使う。調査にない指標は標準 |
| TKC（自分で入力） | 業種名と、指標ごとの「優良企業平均」「黒字企業平均」を利用者が入力（初期値は空）。**BAST の数値はアプリにもリポジトリにも含めない**。未入力の指標は標準 |

### 公開に向けた土台（段階A）

- **免責事項・プライバシー**：設定 →「このアプリについて」と印刷用レポートの注記に表示（計算結果は参考値で、税務・投資等の助言ではない／データは端末内のみで外部に送信しない）。文言は js/help.js
- **初回ガイド**：データがなく、ガイドを見ていない端末で起動すると3画面の案内を表示（アプリの説明 → 使い方と「サンプルで試す」→ バックアップとホーム画面への追加手順）。表示済みの記録は localStorage の `finAnalysisTool.onboarded`。設定 →「このアプリについて」から再表示できる
- **「?」ヘルプ**：分析結果と比較表の指標の「?」で、計算式・意味・評価の目安を表示。設定 →「指標の解説（計算式一覧）」に一覧
- **想定外のエラー**：画面上部に「バックアップを保存」「再読み込み」を表示（index.html の先頭に単独で置き、js/ui.js が読めない場合も動く）。データの保存に失敗している間は、画面上部に常に警告の帯を表示
- **元に戻す**：「クリア」「期を削除」「バックアップから復元」「サンプルデータ読込」「会社の削除」「CSVの取込」の直前の状態を1つだけ端末内（`finAnalysisTool.undo`）に退避。操作直後の通知の「元に戻す」か、設定 →「バックアップ・データ管理」から戻せる。「すべてのデータを削除」では退避データも消す

### 試算表CSVの取込（段階B）

入力タブの「試算表CSVを取り込む」で、会計ソフトなどから書き出した試算表・決算書のCSVを、選択中の期に入力できます（js/importer.js、画面は js/ui/import-view.js）。

- **形式**：1行に「科目名」と「金額」が並んだCSV（汎用形式）。科目名 = 行の最初の数値でない列、金額 = 行の最後の数値の列（前期・当期の列があれば当期）。見出し・空行は読み飛ばす。カンマ区切りのほか、1行目にタブがあればタブ区切り（Excelからの貼り付け）。文字コードは UTF-8（BOM可）と Shift_JIS を自動判定。金額は `1,234`・`¥1,234円`・`△500`・`(500)`・全角数字に対応
- **金額の単位**：取込時に円・千円・百万円から選ぶ（既定は円）。内部では千円で保存
- **科目の対応**：よく使う科目名（売上高・販売費及び一般管理費・現金及び預金・売掛金・短期借入金など）は自動で候補を出す。営業損失・経常損失・当期純損失は符号を反転して利益の欄に入れる。科目名は空白・番号（Ⅰ．、(1) など）・全角を整えてから照合
- **二重計上の防止**：同じ入力項目に合計の科目（例：現金及び預金合計）と内訳の科目（例：現金・普通預金）があると、自動の候補では合計の1行だけを選び、内訳は「取り込まない」にする。合計がなければ内訳を合算する（例：短期借入金＋長期借入金 → 有利子負債）
- **対応表の保存**：利用者が選び直した対応だけを保存し（全社共通、最大1000件）、次回同じ科目名なら同じ項目を選ぶ。自動の候補は保存しない
- **取り込み**：取り込んだ項目だけを上書きし、ほかの入力・調整項目はそのまま。内訳科目の合計で計算している項目は取込先に出さない。取り込み直後の通知か、設定 →「バックアップ・データ管理」から「元に戻す」で取り消せる（対応表は元に戻しても残る）
- **会計ソフト別の形式**（freee・マネーフォワード・弥生など）は未対応（今後、対象を決めて追加）

### 計算できない場合の表示

| 表示 | 条件 |
| --- | --- |
| — | 分母が 0、または計算に必要な項目が未入力 |
| 参考外 | 債務超過（純資産 < 0）のときの ROE・D/Eレシオ・固定比率 |
| 参考外 | 固定長期適合率で、自己資本 + 固定負債 < 0 |

自己資本比率は債務超過でもマイナス値のまま表示します。赤字の利益率・ICR、ネットキャッシュ（ネットデットがマイナス）もマイナス値で表示します。

### チェック

- 総資産 ≠ 流動資産 + 固定資産 → 差額を表示して警告
- 総資産 ≠ 流動負債 + 固定負債 + 純資産 → 差額を表示して警告
- 差額の絶対値が 0.0005千円（0.5円）未満は一致とみなします（小数計算の誤差対策）
- 必要な項目が未入力の間は判定しません

### 保存形式（version 10：複数社）

localStorage の `finAnalysisTool.data` には、全社分をまとめたワークスペースを保存します（js/workspace.js）。

```json
{
  "version": 10,
  "activeId": "co-…",
  "companies": [ { "id": "co-…", "companyName": "サンプル株式会社", "periods": [ "…" ], "reportComment": "" } ],
  "settings": { "…": "全社共通の設定（下の1社分のデータの settings と同じ）" },
  "importMap": { "製品売上": "pl.sales", "雑収入": "ignore" }
}
```

- 画面は選択中の会社のデータ（下の1社分のデータと同じ形）を扱い、保存のときにワークスペースへ書き戻します
- 会社は最大30社。設定（単位・科目・指標・評価基準など）は全社共通です
- `importMap` は試算表CSV取込の科目の対応表（正規化した科目名 → 入力項目。`ignore` は取り込まない）。全社共通
- **version 7 以前のデータは、そのまま1社目として移行**します（`migrateV7toV8`。金額・設定・計算結果は変わりません）
- バックアップは「この会社のバックアップ」（従来と同じ1社分の形式。`data` が1社分のデータ version 8）と「全社のバックアップ」（`data` がワークスペース。ファイル名 `fin-tool-backup-all-YYYY-MM-DD.json`）の2種類。1社分を復元するときは、新しい会社として追加するか、選択中の会社に上書きするかを選びます。全社分は全体を置き換えます
- 「元に戻す」の退避（`finAnalysisTool.undo`）は全社分を1つ保存します（会社の削除も戻せます）

## 更新時の手順（重要）

アプリのファイル（HTML / CSS / JS / アイコン / manifest）を変更したら、**必ず `sw.js` のキャッシュのバージョンを上げてください。** 上げ忘れると、利用者の端末では古いファイルが表示され続けます。

1. ファイルを変更する
2. 新しいファイルを追加した場合は、`sw.js` の `ASSETS` に追加する
3. `sw.js` の `CACHE_VERSION` を 1 つ上げる（例：`'v1'` → `'v2'`。キャッシュ名は `fin-tool-v2` になる）
   - 同時に `js/pwa.js` の `APP_VERSION` も同じ値にする（設定 → このアプリについてに表示。check-pwa で一致を確認）
   - 利用者に知らせたい変更があれば `js/changelog.js` の `CHANGELOG` の先頭に追加する（テストで先頭が `APP_VERSION` と一致することを確認）。更新後の最初の起動時に、前回のバージョンからの変更点を表示する（前回のバージョンは localStorage の `finAnalysisTool.lastVersion`）
4. `node --test` と `node scripts/check-pwa.js` がすべて通ることを確認する
5. コミットして GitHub に push する（GitHub Pages に数分で反映）
6. 利用者が次にアプリを開くと「新しいバージョンがあります［更新］」が表示され、［更新］で切り替わる。古いキャッシュはこのとき削除される

## アイコンの作成手順

- 元データ：`icons/icon.svg`（アプリ名「数字のミカタ」に合わせた案A「ルーペ」：ティール→ブルーのグラデーション背景に、棒グラフと上昇線をのぞくルーペ。オリジナル図形で、実在のブランドには似せていません。背景は全面塗りで、図形は maskable の安全領域内に収めています）
- 変換ツール：Playwright（Chromium）で SVG を表示し、180 / 192 / 512px のスクリーンショットを PNG として保存
- 手順：

```sh
npm install --no-save playwright   # 未導入の場合のみ
npx playwright install chromium    # 未導入の場合のみ
node scripts/build-icons.cjs
```

アイコンを作り直したら、上の「更新時の手順」に従ってキャッシュのバージョンを上げてください。

## ローカルでの確認

ES Modules を使っているため、`index.html` をダブルクリックで開く（file://）と動きません。簡易サーバーを起動して開いてください。

```sh
python3 -m http.server 8000
# または: npx serve .
```

ブラウザで http://localhost:8000/ を開きます。

## GitHub Pages での公開手順

1. GitHub のリポジトリ画面で **Settings → Pages** を開く
2. **Build and deployment** の Source を「Deploy from a branch」にする
3. Branch を `main`、フォルダを `/ (root)` にして **Save**
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される
5. iPhone の Safari で開き、共有ボタン →「ホーム画面に追加」でアプリとして使える

Service Worker は HTTPS（GitHub Pages は対応済み）または localhost でのみ動作します。

注意：保存データは端末・ブラウザごとに別です。Safari の「履歴とWebサイトデータを消去」を行うとデータも消えます。
